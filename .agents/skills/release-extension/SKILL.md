# 发布 Chrome 扩展

把用户的明确发布意图视为对版本提交、推送和创建标签的授权。持续执行到发布工作流结束，不逐项征求确认。

## 准备工作区

1. 检查当前分支和工作区状态，确认功能代码已经由发布流程之外的任务提交完成。
2. 要求位于 `main` 且工作区干净。存在未提交改动时停止并报告，不在本 skill 内组织、暂存或提交功能代码。

## 确定版本

1. 检查当前扩展版本、最近的 `v*` 标签，以及该标签至 `HEAD` 的提交和差异。
2. 综合功能范围、用户可见行为、兼容性与代码改动量判断 SemVer：
   - 不兼容变更使用 major；项目仍处于 `0.x` 时通常递增 minor。
   - 向后兼容的新功能使用 minor。
   - 缺陷修复、内部优化和纯文档改动使用 patch。
3. 用户指定版本时遵循用户要求；未指定时自主判断，不机械递增 patch，也不反问用户。

## 执行发布

1. 执行 `mise exec -- pnpm release:extension <version>`，保留会话直到脚本结束。
2. 让脚本再次确认 `main` 与干净工作区，更新扩展版本，完成类型检查、测试、构建和依赖检查，随后创建独立版本提交和标签、原子推送 `main` 与标签，并等待 `.github/workflows/publish-chrome.yml` 完成。
3. 不要额外手工提交、推送或移动标签，除非脚本失败且已先检查本地与远端的精确状态。

## 交付结果

报告发布版本、标签、版本提交、GitHub Actions 地址和最终结果。工作流失败或未确认已提交 Chrome Web Store 审核时，明确报告阻塞点，不得声称发布成功。
