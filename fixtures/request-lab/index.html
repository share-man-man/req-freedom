LOCAL FIXTURE · REQUEST LAB

ReqFreedom 请求实验室

一个零依赖的静态页面，用来观察规则对浏览器请求和页面行为的影响。

页面脚本已就绪
使用方式：使用任意 Node 静态服务托管本目录，打开页面后按卡片中的规则示例配置插件；每次请求的 URL、状态、耗时和响应会显示在下方日志中。Header 改写请同时在 DevTools Network 中查看真实请求/响应头。

NETWORK LAYER · DNR

网络层

作用于全部请求（含页面导航、静态资源），但读不到请求体。

拦截 / 重定向 / 参数注入三选一，Header 改写可叠加。

COOKIE

Cookie 双向

响应回显收到的 Cookie 请求头，同时下发三条可见性各异的 Set-Cookie。两个方向的改写都能在此核对（首次点击尚无 Cookie 可回显，再点一次即可看到）。

GET /api/cookies
三条 Cookie 的可见性 
lab_visible  Path=/     document.cookie 可见
lab_scoped   Path=/api  仅接口路径回传，页面读不到
lab_session  HttpOnly   JS 一律读不到，只能在
                        Network 面板核对
CROSS ORIGIN

跨域 / CORS

请求另一个端口上的服务（不同源）。「被拦」端点故意不发 CORS 头，浏览器会拦下响应；「对照」端点主动放行，用来证明服务确实可达。

另一端口的跨域服务
解除 CORS 规则示例 
匹配：contains /api/cross-origin/blocked
类型：Header 改写
作用于：响应头
操作：设置
Access-Control-Allow-Origin = *

注意：CORS 由浏览器在网络层裁决，
页面补丁通道看不到被拦下的响应，
只能用 DNR 通道的响应头改写解除。
FETCH

不透明响应 / 未能应用

以 mode: 'no-cors' 请求跨域端点，浏览器返回不透明响应（状态码 0、响应体不可读）。「基于真实响应」的 Mock 在其之上无从改写，只能原样放行。

no-cors → /api/cross-origin/opaque
预期表现 
规则：基于真实响应的 Mock，匹配 /api/cross-origin/opaque
请求：正常完成，但日志里状态码为 0、响应体为空
popup：该规则显示黄色禁止图标，悬停说明「响应不透明，读不到响应体」
计数：不计入命中——动作确实没有发生
XHR

同步 XHR / 未能应用

用已废弃的同步 XHR 发起请求。页面补丁通道的处理全是异步的，插进去只会让页面读到空响应，因此扩展刻意 fail-open 原样放行。

/api/sync-xhr.json
预期表现 
规则：返回值 Mock，匹配 /api/sync-xhr.json
请求：读到服务端真实内容，而不是 Mock 响应体
popup：该规则显示黄色禁止图标，悬停说明「同步 XHR 容不下异步处理」
控制台：页面控制台另有一行说明，同时浏览器会给出同步 XHR 的弃用警告
DNR

非法规则 / 注册失败

示例配置里带了一条浏览器会拒绝的规则：正则用了前瞻断言，JS 认、DNR 的 RE2 引擎不认。请求应当正常返回，插件里那条规则会被标为未被浏览器接受，且不产生命中。

/api/registration-probe.json
预期表现 
规则：regex /api/registration-probe(?=\.json) + 拦截
请求：正常返回 200（规则没生效）
popup：该规则右侧显示红色警告图标，且不计入命中
管理页：被拒绝的动作标签变红，悬停可见浏览器原始报错
其余规则：照常生效——整批提交失败后会降级为逐条注册以隔离非法规则

GRAPHQL

operationName 区分

两个操作共用同一 URL 和方法，只能靠请求体里的 operationName 区分。响应回显服务端实际收到的操作名与变量。

POST /api/graphql
为什么只靠 URL 匹配不够 
ListItems 与 GetUser 的 URL、method 完全相同，
只有请求体不同。仅按 URL 匹配会同时命中两者，
需要「请求体匹配」才能只改其中一个。
