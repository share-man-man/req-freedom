# 快速开始

## 环境要求

- Node.js >= 22（推荐使用 [mise](https://mise.jdx.dev/) 管理，仓库已提供 `mise.toml`）
- pnpm 9

## 安装依赖

```bash
mise exec -- pnpm install
```

## 本地开发

```bash
# 启动插件开发模式（自动打开带插件的 Chrome）
mise exec -- pnpm dev

# 启动文档站
mise exec -- pnpm dev:docs
```

## 构建

```bash
# 构建全部（插件 + 文档站）
mise exec -- pnpm build
```

插件产物位于 `apps/extension/.output/chrome-mv3/`，可在 `chrome://extensions` 开启开发者模式后「加载已解压的扩展程序」。

## 创建第一条规则

1. 点击浏览器工具栏中的插件图标，打开 popup
2. 点击「管理规则」进入规则管理页
3. 点击「+ 返回值 Mock」创建示例规则，按需修改匹配模式后勾选启用

## 查看规则命中

规则动作执行后，扩展图标徽标会立即显示当前标签页的**原生动作计数**：

- DNR 通道直接使用浏览器记录的动作数；同一业务规则一次请求若执行重定向与 Header 改写两个动作，会计为 2。
- 页面补丁通道把本次实际采用的 Mock、延迟、改请求体或脚本注入动作增量并入同一个原生计数器。

打开 popup 时会显示相同的动作总数。已产生动作的规则会高亮，规则卡片右上角的角标显示该规则累计产生的动作数；点击规则后的跳转按钮，可进入规则管理页并自动定位、高亮对应规则。「清空」按钮会同时重置当前标签页的动作总数、逐规则角标、高亮状态和扩展图标徽标。

统计读取失败时 popup 会显示重试入口，不会把失败误显示成 0。升级前已删除、无法恢复业务规则映射的少量历史 DNR 动作仍计入总数，并会单独标明；它们不会错误归到当前规则。
