# 快速开始

## 环境要求

- Node.js >= 22（推荐使用 [mise](https://mise.jdx.dev/) 管理，仓库已提供 `mise.toml`）
- pnpm 9

## 安装依赖

```bash
mise exec -- pnpm install
```

## 本地开发

```bash
# 启动插件开发模式（自动打开带插件的 Chrome）
mise exec -- pnpm dev

# 启动文档站
mise exec -- pnpm dev:docs
```

## 构建

```bash
# 构建全部（插件 + 文档站）
mise exec -- pnpm build
```

插件产物位于 `apps/extension/.output/chrome-mv3/`，可在 `chrome://extensions` 开启开发者模式后「加载已解压的扩展程序」。

## 创建第一条规则

1. 点击浏览器工具栏中的插件图标，打开 popup
2. 点击「管理规则」进入规则管理页
3. 点击「+ 返回值 Mock」创建示例规则，按需修改匹配模式后勾选启用

## 查看规则命中

规则动作执行后，扩展图标徽标会立即点亮一个小圆点，表示**当前标签页有规则生效**。徽标只表达状态，不显示数字。

打开 popup 可以看到细节：

- 顶部显示本页命中过的**规则条数**（按规则去重，同一规则触发多次只算一条）。
- 命中过的规则会高亮，并在右侧显示一个闪电图标。
- 点击任意规则名即可进入规则管理页并自动定位、高亮该规则。
- 「清空」按钮会重置当前标签页的命中日志、高亮状态与图标徽标。

命中日志在顶层导航开始时自动清空，Hash 与 SPA 同文档跳转不会重置；主文档被规则重定向属于同一次导航，命中会保留到跳转后的页面。

iframe 内部的请求只有 DNR 通道的规则会命中并计入；页面补丁通道（Mock、网络限速、改请求体、脚本注入）只作用于顶层文档，在子框架内不生效，因此也不会产生命中，详见[已知限制](./architecture.md#已知限制)。

单个标签页最多保留最近 1000 条命中；超出后会丢弃最早的记录并在 popup 中提示。

同时最多保留 30 个标签页的命中日志，超出后整份丢弃最久未更新的那个标签页 —— 被丢弃的标签页统计归零，但不会出现某个标签页只剩半截数据的情况。
